# Agent 岗位面试口述要点

这份稿子不是背诵答案。先用自己的项目跑一遍，再用下面的结构讲清“做了什么、为什么这样做、证据在哪里、下一步怎么演进”。

## 1. 一分钟项目介绍

> 我基于现有 Vue 办公助手做了一个本地 Agent Workbench。前端保留原聊天体验，local-agent 模式绕开公司 SSO，通过 Vite Proxy 请求 Fastify 后端。后端把模型适配、模型原生 Agent Loop、工具策略、动态 MCP、文件 RAG、Redis Run 状态和 Trace 拆开。重点不是让模型看起来聪明，而是让一次执行可控、可观察、可回归。工作台里能直接看到模型流、工具输入输出、Run 状态与耗时。

## 2. 为什么不直接用 Agent 框架

> 框架可以加速接入，但我先实现了最小可控的 Loop，目的是理解并掌握边界。Planner、Executor、Trace、Memory 和模型适配都是独立模块，因此之后接入 LangGraph 或其他框架时，框架只是编排层，不会吞掉我的权限、评测和观测设计。实际选型取决于团队已有生态、任务复杂度和可维护性，不是为了“用了框架”而用。

## 3. Prompt、Context、Harness 分别做什么

> Prompt 定义角色、输出格式和行为边界；Context 是本轮真正送给模型的、经过检索和预算控制的信息；Harness 是模型之外的工程控制系统，包括工具 allowlist、参数校验、超时、重试、预算、Trace 和评测。Prompt 不能替代 Harness，因为模型不能被当作权限系统。

## 4. Agent Loop 怎么设计

> 一次请求先检索当前用户的记忆和知识片段，再把工具 JSON Schema 与上下文交给模型。模型返回 tool calls 后，执行器校验工具、执行并把 observation 回填模型；模型决定是否继续调用，直到输出最终回答。停止条件包括最大步骤数、模型超时、工具超时和用户停止。模型只提出动作，服务端仍决定哪些工具实际可执行。

## 5. Tool、Skill、MCP 的区别

> Tool 是受控能力单元，比如计算、检索或生成文件；Skill 是可复用的完成方法，比如技术评审的输出步骤；MCP 是外部能力标准化接入协议。项目把 MCP Server 配置加密存到数据库，运行时按 stdio、SSE 或 Streamable HTTP 动态 list tools，再将工具 Schema 给模型。模型只能提议调用，真正执行必须通过服务端 registry。

## 6. Memory 和 RAG 怎么做

> 我区分会话日志、用户长期记忆和系统知识。长期记忆通过受权限保护的 API 显式写入；知识文件先存 MinIO，再解析、分块、embedding 写入 pgvector。每轮只注入命中的少量片段，避免全量历史造成成本、相关性和权限问题。embedding 不可用时上传明确失败，不会用空向量伪造检索成功。

## 7. 何时使用 Multi-Agent

> 我不会默认上多 Agent。独立研究、并行审阅、角色制衡时才拆；简单任务、强依赖任务、成本敏感任务先用单 Agent。项目中 planner 和 reviewer 并发运行，synthesis 统一汇总，Trace 保留各自输入、输出和耗时。评估要比较任务完整率、冲突率、P95 延迟和单位任务成本，而不是只看答案变长了。

## 8. 怎样定位失败

> 我从 Run 和 Trace 开始：模型请求失败会留下 `RUN_FAILED` 与具体错误；type 12 工具事件为 error 说明工具、参数或超时问题；知识检索为空说明数据、embedding 或召回问题；达到 `maxSteps` 说明任务没有收敛；服务重启会把 running Run 标记为 `interrupted`。离线固定评测防止版本回归，在线 Trace 用于解释某一次真实失败。

## 9. 当前局限与下一步

> 当前展示版将平台 V1 的身份、会话、知识库、向量、Trace 和评测，以及旧前端兼容接口的状态，统一存入 PostgreSQL + pgvector；Redis 保存 Run 临时状态，MinIO 保存原始文件，不使用本地 JSON 文件。生产下一步是：工具引入 tenant ACL、审批和幂等，接入真实业务检索/工单能力，增加任务正确率和引用正确性评测，并以队列和并发预算管理长任务。

## 10. 联网搜索和沙盒如何落地

> 我把“模型能提出动作”和“平台允许执行动作”分开。联网搜索由本地 SearXNG 统一出口，Agent 只能传查询词，不能指定任意请求地址；返回结果保留来源链接，回答只能基于实际结果。代码执行在独立 Docker 容器，执行容器在 internal 网络中，通过仅本机可访问的网关接收后端请求；容器只读、非 root、无 capabilities，并受 CPU、内存、进程数和超时限制，后端到沙盒还需要共享 token。Node `vm` 是语言层约束，真正隔离依赖容器；如果要做多租户，我会进一步使用 gVisor、Kata 或 Firecracker。

## 高频追问速答

| 追问 | 回答方向 |
| --- | --- |
| 为什么模型不能直接调用接口？ | 模型不可信且容易受提示注入影响；必须由服务端策略层决定可调用能力。 |
| 为什么需要 MCP？ | 当外部能力需要跨语言、跨宿主标准接入时，MCP 减少定制 adapter；内部简单工具无需为了 MCP 而 MCP。 |
| 怎么控制成本？ | 限制步骤、检索 top-k、模型分级、并发预算、缓存和离线评测；用 P95 延迟和单位任务成本衡量。 |
| 怎么防止幻觉？ | 不承诺完全消除；用检索证据、工具结果约束、结构化输出校验、引用检查和人工兜底降低风险。 |
| 如何上线？ | 灰度、任务白名单、只读工具先行、完整审计、离线评测门禁、线上告警与可回滚配置。 |
