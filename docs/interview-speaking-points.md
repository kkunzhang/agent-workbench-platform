# Agent 岗位面试口述要点

这份稿子不是背诵答案。先用自己的项目跑一遍，再用下面的结构讲清“做了什么、为什么这样做、证据在哪里、下一步怎么演进”。

## 1. 一分钟项目介绍

> 我基于现有 Vue 办公助手做了一个本地 Agent Workbench。前端保留原聊天体验，local-agent 模式绕开公司 SSO，通过 Vite Proxy 请求 Fastify 后端。后端把模型适配、Agent Loop、工具策略、真实 MCP Client、记忆、Trace 和评测拆开。重点不是让模型看起来聪明，而是让一次执行可控、可观察、可回归。工作台里能直接看到计划、工具输入输出、模型来源、耗时与评测结果。

## 2. 为什么不直接用 Agent 框架

> 框架可以加速接入，但我先实现了最小可控的 Loop，目的是理解并掌握边界。Planner、Executor、Trace、Memory 和模型适配都是独立模块，因此之后接入 LangGraph 或其他框架时，框架只是编排层，不会吞掉我的权限、评测和观测设计。实际选型取决于团队已有生态、任务复杂度和可维护性，不是为了“用了框架”而用。

## 3. Prompt、Context、Harness 分别做什么

> Prompt 定义角色、输出格式和行为边界；Context 是本轮真正送给模型的、经过检索和预算控制的信息；Harness 是模型之外的工程控制系统，包括工具 allowlist、参数校验、超时、重试、预算、Trace 和评测。Prompt 不能替代 Harness，因为模型不能被当作权限系统。

## 4. Agent Loop 怎么设计

> 一次请求先形成有最大步骤数的计划，再由执行器对每个工具做注册和策略校验，执行结果被作为 observation 回填。最后回答层只能使用已经执行的证据。当前用规则规划器保证演示稳定，但 executor 和 planner 已解耦；后续可以让模型提出 tool calls，再经过同一套校验执行。停止条件包括步骤预算、模型超时、工具失败与用户停止。

## 5. Tool、Skill、MCP 的区别

> Tool 是受控能力单元，比如计算、检索或写工单；Skill 是可复用的完成方法，比如技术评审的输出步骤；MCP 是外部能力标准化接入协议。项目中 `mcp_add` 不是假返回，它通过 stdio MCP Client 调用独立 MCP Server。模型只能提议调用，真正执行必须通过服务端 registry。

## 6. Memory 和 RAG 怎么做

> 我区分会话日志、用户长期记忆和系统知识。用户明确要求“记住”的内容写入长期记忆，检索时优先 embedding 相似度，模型不可用时词法降级；系统知识通过单独知识库检索。每轮只注入命中的少量片段，避免全量历史造成成本、相关性和权限问题。生产会增加 tenant、ACL、TTL、来源和删除能力，并采用 Postgres/pgvector 或独立向量库。

## 7. 何时使用 Multi-Agent

> 我不会默认上多 Agent。独立研究、并行审阅、角色制衡时才拆；简单任务、强依赖任务、成本敏感任务先用单 Agent。项目中 planner 和 reviewer 并发运行，synthesis 统一汇总，Trace 保留各自输入、输出和耗时。评估要比较任务完整率、冲突率、P95 延迟和单位任务成本，而不是只看答案变长了。

## 8. 怎样定位失败

> 我从 Trace 开始：如果 model Span 的 source 是 fallback，就是模型或网关问题；tool Span error 说明工具、参数或超时问题；知识检索为空说明数据或召回问题；步骤超预算说明 planner 或任务拆分问题；没有 SSE FINISHED 才回到传输层排查。离线固定评测防止版本回归，在线 Trace 用于解释某一次真实失败。

## 9. 当前局限与下一步

> 当前实现为了本地可跑和面试演示，存储用 JSON，知识库规模小，规则规划器是基线，Ollama 小模型在并发子 Agent 上会有质量和资源限制。生产下一步是：将存储替换为 Postgres + pgvector，工具引入 tenant ACL、审批和幂等，接入真实业务检索/工单能力，增加任务正确率和引用正确性评测，并以队列和并发预算管理长任务。

## 高频追问速答

| 追问 | 回答方向 |
| --- | --- |
| 为什么模型不能直接调用接口？ | 模型不可信且容易受提示注入影响；必须由服务端策略层决定可调用能力。 |
| 为什么需要 MCP？ | 当外部能力需要跨语言、跨宿主标准接入时，MCP 减少定制 adapter；内部简单工具无需为了 MCP 而 MCP。 |
| 怎么控制成本？ | 限制步骤、检索 top-k、模型分级、并发预算、缓存和离线评测；用 P95 延迟和单位任务成本衡量。 |
| 怎么防止幻觉？ | 不承诺完全消除；用检索证据、工具结果约束、结构化输出校验、引用检查和人工兜底降低风险。 |
| 如何上线？ | 灰度、任务白名单、只读工具先行、完整审计、离线评测门禁、线上告警与可回滚配置。 |
