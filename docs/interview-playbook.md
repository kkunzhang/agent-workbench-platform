# 面试讲解提纲

先用一句话描述项目：这是一个在现有办公助手前端上实现的 Agent Workbench，目标是把模型输出放进可控、可观测、可回归的执行系统。

然后按一次请求展开：前端走 SSE；后端生成受步骤预算限制的计划；调用具有超时和重试策略的工具；把证据加入上下文；模型或确定性工具给出答案；最后持久化 Trace 和评测。

重点取舍：规则规划器不是终点，而是为了演示稳定和安全选的基线；执行器已与规划器解耦，因此能替换为模型 tool calling。JSON 是本地开发实现，接口边界预留给 Postgres/pgvector。多 Agent 只在独立审阅或并行研究时启用，因为它增加延迟、成本和上下文汇总风险。

准备一个失败案例：关闭 Ollama 时模型适配器回落到教学回复；Trace 能显示模型来源为 fallback，工具 Span 仍可区分是否成功。这比只说“模型不稳定”更可验证。
