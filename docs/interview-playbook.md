# 面试讲解提纲

先用一句话描述项目：这是一个在现有办公助手前端上实现的 Agent Workbench，目标是把模型输出放进可控、可观测、可回归的执行系统。

然后按一次请求展开：前端走 SSE；后端检索当前用户的记忆和知识片段；模型收到工具 Schema 后决定是否发起 Tool Calling；执行器按超时和重试策略执行工具，再把 observation 回写模型；最后持久化消息、Run、步骤和 Trace。

重点取舍：模型负责提出 tool calls，服务端负责 schema、权限、超时、重试和步骤预算；不能把权限交给 Prompt。关系数据和向量进入 Postgres/pgvector，短期 Run 状态进入 Redis，原始文件进入 MinIO。多 Agent 只在独立审阅或并行研究时启用，因为它增加延迟、成本和上下文汇总风险。

准备一个失败案例：关闭 Ollama 时 Run 会以模型连接错误结束；工具错误、RAG 失败和服务重启分别留下可区分的错误码与步骤记录。这比只说“模型不稳定”更可验证。
